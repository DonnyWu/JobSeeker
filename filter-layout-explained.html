🧱 Tidying up the Job Search filter layout

JobSeeker · how Streamlit columns work, and how we used them to fix two layout annoyances — written for a junior dev

TL;DR — The Job Search filters looked a little messy: the Minimum match score slider was stranded on a lower row, and there was an awkward empty gap under the keyword box before the Remote / Applied options showed up. We fixed both purely by rearranging Streamlit columns — no logic changed. Match now sits right next to the distance slider, and Remote/Applied moved up under the keyword box to fill the gap.

🎯 The objective

Two small, purely-visual requests on the Job Search page:

  • 1. Put the match-score slider beside the distance slider. It was way down on a second row, far from the other filters — annoying to reach for.
  • 2. Kill the awkward gap. There was a big chunk of empty space between the Job title / keywords box and the Remote only checkbox. It looked broken, like something failed to load.

Nothing about how search works needed to change — this is 100% layout. To fix it cleanly you first have to understand the one Streamlit concept that caused the mess: columns.

First, how st.columns actually works

In Streamlit you make a row of side-by-side columns with st.columns([...]). Three things trip people up:

  • 🔢 The numbers are ratios, not pixels. st.columns([3, 3, 2]) means three columns that share the width 3 : 3 : 2. [3, 3, 3] is just three equal columns.
  • 📚 Each column is its own top-to-bottom stack. Everything you put inside with col2: stacks vertically inside that column only.
  • 📏 A row is as tall as its tallest column. This is the important one — it's exactly what caused the gap. Keep reading.

the basic shape

col1, col2, col3 = st.columns([3, 3, 3])   # three equal-width columns
with col1:
    st.text_input("Job title / keywords")        # stacks inside col1
with col2:
    st.text_input("Location")
    st.slider("Search radius (miles)")         # col2 now has TWO things → it's taller

Why the awkward gap happened

The filters used two separate rows of columns. The top row's keyword column held just one widget, but its neighbors each held two (an input plus a slider). Because a row is as tall as its tallest column, the keyword column got padded with empty space down to match its taller neighbors — and the second row (Remote/Applied) couldn't begin until that whole tall first row finished. That stretch of nothing under the keyword box was the gap.

The fix, in three moves

Move 1 — match slider goes next to distance

We widened the top row from [3, 3, 2] to [3, 3, 3] (equal thirds, so the sliders line up at the same width), then dropped the Minimum match score slider into the third column, right under Posted within — which puts it directly to the right of the distance slider.

pages/3_Job_Search.py

col1, col2, col3 = st.columns([3, 3, 3])      # was [3, 3, 2]
...
with col3:
    time_filter = st.selectbox("Posted within", ...)
    min_score   = st.slider("Minimum match score", ...)   # moved up here, beside distance

Move 2 — Remote / Applied move up under the keyword box

To fill the empty space, we put the Remote only checkbox and Applied jobs radio into the same column as the keyword box (col1), right beneath it. Now that short column has three stacked widgets instead of one — so there's no leftover space to look awkward.

pages/3_Job_Search.py

with col1:
    query     = st.text_input("Job title / keywords", ...)
    is_remote = st.checkbox("Remote only", ...)          # moved up
    applied_view = st.radio("Applied jobs", ...)        # moved up

Move 3 — the Search button gets its own line

With Remote/Applied gone from the second row, all that's left there is the button. We gave it a simple [8, 2] split and stuck it in the narrow right column so it stays right-aligned.

pages/3_Job_Search.py

_bcol1, _bcol2 = st.columns([8, 2])
with _bcol2:
    search_clicked = st.button("Search", type="primary", use_container_width=True)
💡 Jr dev note — order in the code = order on screen Inside a with col: block, widgets render in the order you write them, top to bottom. So "move it up under the keyword box" literally means "move those lines up so they're written right after the keyword input." There's no separate position/CSS to set — the layout is the code order.
💡 Jr dev note — a variable is "born" where you create it Moving is_remote and min_score higher up is safe because Python reads top-to-bottom: a variable just has to be created before it's used. The search logic that reads min_score and is_remote runs later in the file, so defining them earlier is totally fine. (Move a variable below the code that uses it and you'd get a NameError — that's the thing to watch for.)

The takeaway

Most Streamlit "why is there a weird gap?" bugs come down to one column being taller than its neighbors, because a row stretches to its tallest column. The fix is almost always: balance what's in each column, or merge widgets into one column so nothing is left half-empty. No CSS required.
