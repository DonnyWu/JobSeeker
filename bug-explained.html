🐛 Why your jobs were coming back unscored

JobSeeker · diagnosis of the “every job is 0/100” problem

TL;DR — Your Groq API key was correct. The bug was that the app loaded the .env file while the key was still empty, and Python’s load_dotenv() refuses to overwrite a value it already loaded. So even after you pasted your key in, the running app kept using the old empty one — every Groq call failed, and a broad except quietly stamped score = 0 on every job. Restarting the app fixes it.

Bug #1 — The stale (empty) API key root cause

Here is the exact sequence of what happened in this session:

App starts — app.py runs load_dotenv()

At that moment .env contained GROQ_API_KEY= (empty).

os.environ["GROQ_API_KEY"] = "" ← empty string is now “set”

You paste your real key into .env

The file on disk is now correct: GROQ_API_KEY=gsk_…

You search jobs → Streamlit reruns → load_dotenv() runs again

But load_dotenv() defaults to override=False. It sees the variable is already set (to "") and skips it.

os.environ["GROQ_API_KEY"] is STILL "" ← your new key never gets read

Scoring calls Groq with an empty key

src/job_matcher.py → _get_client() → Groq(api_key="") → the API rejects it and raises.

The error is swallowed and every job gets a 0

The try/except in rank_jobs catches everything and assigns a fallback score.

score = 0, reason = "scoring unavailable" ← looks like “0/100 match”

Fix: restart the app

A fresh process runs load_dotenv() when .env already has the key, so os.environ gets the real value.

os.environ["GROQ_API_KEY"] = "gsk_…" ← scoring works ✓

The two lines that hid the problem

src/job_matcher.py — the fallback that turns an API failure into a silent “0”

try:
    batch_scores = _score_batch(client, summary, skills, batch)
    scores.extend(batch_scores)
except Exception:                       # ← catches the auth error and hides it
    for job in batch:
        scores.append({"job_id": job["job_id"],
                       "score": 0,                 # ← every job becomes 0/100
                       "reason": "scoring unavailable"})
⚠️ Why this is sneaky: a “bad fit” job and a “the API key is broken” job both end up as 0. From the UI they look identical, so it seems like the matcher decided every job is a 0/100 match — when really it never scored anything at all.

This one doesn’t stop scoring, but it makes the scores worse than they should be. The job scorer is told to compare each job against your summary + skills, but the summary is always blank.

Remember this rule

📌 Editing .env while the app is running does nothing. You must restart Streamlit for a key change to take effect — because of the load_dotenv(override=False) behavior shown above.
