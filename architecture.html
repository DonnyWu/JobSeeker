JobSeeker Architecture

AI-powered job matching and auto-apply — built with Streamlit, Groq (Llama 3.3), python-jobspy, and Playwright.

Overview

JobSeeker eliminates manual job hunting. The user uploads a resume, the app parses it, scrapes five major job boards simultaneously, ranks every result against the resume using an LLM, and then opens a real browser to auto-fill the application form — pausing before submit so the user stays in control.

Source Modules

profile_manager.py

Single source of truth for all SQLite reads and writes. Initialises the three tables on startup and exposes simple get/save functions used by every page.

resume_parser.py

Two-stage pipeline: extract raw text from the file (pdfplumber for PDF, python-docx for DOCX), then parse the text by sending it to Groq with a structured JSON prompt. Returns skills, experience, and education arrays.

job_scraper.py

Thin wrapper around python-jobspy. Accepts the UI's time-filter label (e.g. "Last 3 days") and maps it to an hours_old integer before calling the scraper across all five boards simultaneously. Returns a pandas DataFrame.

job_matcher.py

Takes the scraper DataFrame and the parsed resume, batches jobs into groups of 10 (to stay within token limits), and sends each batch to Groq with a scoring prompt. Returns the DataFrame sorted by match score descending.

company_finder.py

Uses Google search to find the company's own careers page for a given job title. Filters out aggregator domains (LinkedIn, Indeed, etc.) and falls back to the original job board URL if nothing credible is found within three results.

autofill.py

Async Playwright function that opens a headed Chromium window, iterates over all visible input fields, maps each one to a profile field using name, aria-label, placeholder, and adjacent <label> text, fills matched fields, then calls page.pause() so the user reviews before submitting.

Data Flows

Resume Upload Flow

  1. Upload — user selects a PDF or DOCX in the Streamlit file uploader.
  2. Save — raw bytes written to uploads/.
  3. Extract — pdfplumber or python-docx reads the file and returns a plain text string.
  4. Parse — raw text is sent to Groq (Llama 3.3 70B) with a structured extraction prompt.
  5. Store — the returned JSON (skills, experience, education) plus the raw text are written to the resume table in SQLite.
  6. Display — parsed data is shown in expandable panels on the Resume page.

Job Search & Ranking Flow

  1. Input — user enters keywords, location, time filter, and optional remote toggle.
  2. Scrape — job_scraper.py calls python-jobspy which hits LinkedIn, Indeed, Glassdoor, ZipRecruiter, and Google Jobs in parallel.
  3. Rank — if a resume exists, job_matcher.py batches the results (10 at a time) and asks Groq to score each job 0–100 against the resume skills.
  4. Sort — results DataFrame is sorted by match score descending.
  5. Display — ranked table shown with score badge, match reason, and action buttons per row.

Auto-Apply Flow

  1. Select — user optionally clicks "Find on Company Site" to replace the aggregator URL with the company's own careers page.
  2. Save & Navigate — clicking "Auto-Apply" saves the job to SQLite, stores it in Streamlit session state, and navigates to Page 4.
  3. Review — Page 4 shows the job details and profile side-by-side for confirmation.
  4. Launch — "Launch Auto-Fill" opens a headed Chromium window via Playwright in a background thread.
  5. Fill — Playwright scans all visible input fields and fills those that match profile fields by name, aria-label, placeholder, or label text.
  6. Pause — page.pause() halts execution so the user can review and manually click Submit.
